# Actividad Sumativa: Desarrollando API REST

## Descripción

Durante esta semana, el equipo de trabajo realizará la actividad sumativa **Desarrollando API REST**, que consiste en:

- Desarrollar APIs propias en su aplicación web para que otras aplicaciones puedan consumir estos recursos.
- Consumir servicios web externos y utilizarlos dentro de la aplicación.

---

## Paso a Paso

1. **Trabajo en Equipo:**  
   La actividad es grupal y debes trabajar con el mismo equipo que ha desarrollado las actividades anteriores de la asignatura.

2. **Entrega Parte I:**  
   Deben entregar un archivo comprimido (.zip o .7-zip) que contenga:
   - Código fuente de la aplicación.
   - Script de la base de datos.
   - Script con los datos iniciales de las tablas.

3. **Aspectos Evaluados (Sumativa N°1 y N°2):**
   - Desarrollo de software con correcta implementación del front-end.
   - Interfaz gráfica adaptada a mínimo 3 tamaños de pantalla, usando GRID de 12 columnas.
   - Uso de HTML, CSS, Bootstrap y JS/JQuery en sus versiones actuales.
   - Organización grupal usando herramientas colaborativas y repositorios GIT.
   - Todas las pantallas y formularios con sus respectivas validaciones.
   - Backend implementado con Framework Django.
   - Lógica de inicio de sesión y autenticación para diferentes tipos de usuarios.
   - Creación, modificación y eliminación de usuarios.
   - Solución lógica de la aplicación según el tema elegido.
   - Seguridad de acceso a URLs mediante inicio de sesión.

4. **Requerimientos a Integrar:**
   - Crear al menos **2 APIs REST propias** para compartir información con otras aplicaciones.
   - Consumir **2 servicios web externos públicos** relacionados con el tema de la aplicación, mostrando la información en una página interna y manteniendo la lógica de desarrollo.

5. **Consideraciones Iniciales:**
   - El caso de la aplicación debe ser de interés para todo el equipo y estar aprobado por todos.
   - El caso debe cumplir con las siguientes características:
     - Los casos pueden ser similares pero no iguales entre equipos.
     - Al inicio, crear el equipo, seleccionar el tema y subir la información al AVA para recibir sugerencias del docente.
     - Deben existir al menos **2 roles de usuario** con privilegios diferentes (pueden agregar más roles si lo desean).
     - Elegir colores, logos, nombre e imágenes para el desarrollo (pueden guiarse de páginas existentes, pero manteniendo originalidad).
     - Páginas obligatorias:
       - Inicio de sesión
       - Registro de usuarios
       - Recuperar contraseña
       - Modificación de perfil
     - Generar páginas internas según las funcionalidades del sistema por tema elegido.
     - Contraseñas deben contar con al menos **4 validaciones de seguridad** (ejemplo: longitud mínima, caracteres especiales, números, letras, longitud máxima).
     - Formularios con validaciones correspondientes para cada campo.
     - La base de datos debe tener **mínimo 6 tablas** y usar **Oracle** como manejador.
     - La aplicación debe consumir al menos **1 web service externo** y tener como mínimo **1 API REST propia**.
     - No implementar sistemas de pago reales; si necesario, simular pago exitoso mediante una página.

## Temáticas Sugeridas

- **Ventas o Arriendos:**
  - Carrito de compras, registro/modificación de productos, manejo de inventario.
  - Monitoreo de compras por usuario.
  - Mantenedores para clientes, usuarios y productos.

- **Foros:**
  - Secciones de foro, comentarios identificados, valoraciones, monitoreo de temas por usuario.
  - Mantenedores para baneo de comentarios/temas, usuarios y secciones.

- **Servicios:**
  - Generación, modificación/eliminación de órdenes de servicio, monitoreo de equipos en servicio.
  - Ruta de procesos internas, mantenedores para usuarios, servicios, montos, tipos de servicios.

- **Consultas Médicas/Reservas:**
  - Mantenedor para especialistas, usuarios, clientes/pacientes.
  - Reservar, modificar, eliminar horas; atención médica; cobros; historial médico.
  - Visualización de reservas y atenciones por médicos/pacientes.

- **Otro Tema:**
  - Si el caso no se ajusta a las temáticas mencionadas, aclararlo en AVA al describir el tema.
